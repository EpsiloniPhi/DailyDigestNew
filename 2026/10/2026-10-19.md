## 1. Probability & Statistics: Markov Chains, Hitting Times and Stationary Distributions

A huge share of "expected number of steps until..." interview questions are Markov chains in disguise. The skill being tested is not linear algebra: it is choosing the **right state space**, writing the **first-step equations** correctly, and knowing which theorem gives a shortcut (Kac, detailed balance, martingales).

### 1.1 Definitions

A discrete-time Markov chain on a countable state space $S$ is a sequence $X_0, X_1, \dots$ with

$$P(X_{n+1} = j \mid X_n = i, X_{n-1}, \dots, X_0) = P(X_{n+1} = j \mid X_n = i) = P_{ij}.$$

The matrix $P$ is **stochastic**: $P_{ij} \ge 0$ and each row sums to 1. By conditioning on intermediate states (Chapman-Kolmogorov), $P(X_n = j \mid X_0 = i) = (P^n)_{ij}$, and if $\mu$ is the row vector of initial probabilities, the law of $X_n$ is $\mu P^n$.

The Markov property says "the present is a sufficient statistic for the future". The art in interview problems is to **enlarge the state** until this is true. For coin patterns, the state is "the longest suffix of what we have flipped that is a prefix of the target", not "the last flip". For a random walk with a turning cost, the state is (position, direction). If your equations need information that is not in the state, the state is wrong.

**Strong Markov property.** If $\tau$ is a stopping time (the decision $\{\tau = n\}$ depends only on $X_0, \dots, X_n$), then conditional on $\tau < \infty$ and $X_\tau = i$, the chain $(X_{\tau + n})_{n \ge 0}$ is a fresh copy of the chain started at $i$, independent of the past. This is what justifies "the process restarts" arguments, such as "after a T we are back to the beginning".

### 1.2 First-step analysis: hitting probabilities and hitting times

Let $A \subset S$ be a target set and $H_A = \inf\{n \ge 0 : X_n \in A\}$.

**Hitting probabilities.** Let $h_i = P_i(H_A < \infty)$. Conditioning on the first step,

$$h_i = 1 \ (i \in A), \qquad h_i = \sum_j P_{ij} h_j \ (i \notin A).$$

**Expected hitting times.** Let $k_i = \mathbb{E}_i[H_A]$. Then

$$k_i = 0 \ (i \in A), \qquad k_i = 1 + \sum_{j} P_{ij} k_j \ (i \notin A).$$

**Theorem (minimal solution).** $h$ is the *minimal non-negative* solution of its system, and so is $k$ (allowing the value $+\infty$).

*Proof sketch for $h$.* Let $g \ge 0$ be any solution. Substitute the equation into itself $n$ times: for $i \notin A$,
$g_i = P_i(H_A \le 1) + \sum_{j_1 \notin A} P_{i j_1} g_{j_1} = \dots = P_i(H_A \le n) + (\text{non-negative remainder}) \ge P_i(H_A \le n)$. Letting $n \to \infty$ gives $g_i \ge h_i$. $\square$

Why "minimal" matters: on an infinite state space the system can have several solutions. For the simple random walk on $\{0, 1, 2, \dots\}$ with up-probability $p > 1/2$ and target $\{0\}$, the constant $h \equiv 1$ solves the equations, but the true answer is $h_i = (q/p)^i$, the minimal solution. On a **finite** chain where $A$ is reachable from every state, the solution is unique and you can just solve the linear system.

### 1.3 Absorbing chains and the fundamental matrix

Order the states so the transient ones come first and the absorbing ones last:

$$P = \begin{pmatrix} Q & R \\ 0 & I \end{pmatrix}.$$

$Q$ is transient-to-transient, $R$ is transient-to-absorbing. Then:

- $(Q^n)_{ij}$ is the probability of being at transient $j$ at time $n$ starting from $i$, and $Q^n \to 0$.
- **Fundamental matrix** $N = I + Q + Q^2 + \dots = (I - Q)^{-1}$. Entry $N_{ij}$ is the expected number of visits to $j$ starting from $i$ (sum of indicators, linearity of expectation).
- Expected time to absorption: $t = N \mathbf{1}$ (total visits to all transient states).
- Absorption probabilities: $B = N R$, where $B_{ia}$ is the probability of being absorbed in $a$ starting from $i$ (the last transient visit is followed by one jump into $a$).

This is exactly the first-step system in matrix form: $t = \mathbf{1} + Q t$ gives $t = (I - Q)^{-1}\mathbf{1}$.

### 1.4 Classification in one paragraph

States $i$ and $j$ **communicate** if each is reachable from the other; communicating classes partition $S$. A state is **recurrent** if $P_i(\text{return}) = 1$ and **transient** otherwise; equivalently, recurrent iff $\sum_n (P^n)_{ii} = \infty$ (the expected number of returns is infinite). Recurrence is a class property. A recurrent state is **positive recurrent** if the mean return time $m_i = \mathbb{E}_i[T_i^+]$ is finite. The **period** of $i$ is $\gcd\{n \ge 1 : (P^n)_{ii} > 0\}$, also a class property. Every irreducible finite chain is positive recurrent. The 1D and 2D simple random walks are recurrent but **null** recurrent ($m_i = \infty$); in 3D the walk is transient (Polya).

### 1.5 Stationary distributions and Kac's theorem

A probability vector $\pi$ is **stationary** if $\pi P = \pi$: if $X_0 \sim \pi$, then $X_n \sim \pi$ for all $n$.

**Theorem.** An irreducible chain has a stationary distribution iff it is positive recurrent, and then it is unique with

$$\pi_i = \frac{1}{m_i} = \frac{1}{\mathbb{E}_i[T_i^+]} \qquad \text{(Kac's formula).}$$

*Proof sketch (cycle trick).* Fix a reference state $i$. Let $\nu_j$ be the expected number of visits to $j$ during one excursion from $i$ back to $i$ (counting time $0$, not the return). Each step of the excursion goes from somewhere to somewhere, so $\nu_j = \sum_k \nu_k P_{kj}$, that is $\nu P = \nu$. The total length of the excursion is $\sum_j \nu_j = m_i$, and $\nu_i = 1$. Normalizing gives $\pi = \nu / m_i$, so $\pi_i = 1/m_i$. Uniqueness follows from irreducibility (any invariant measure is proportional to $\nu$). $\square$

**Ergodic theorem.** For an irreducible positive recurrent chain and any bounded $f$,
$\frac{1}{n}\sum_{k<n} f(X_k) \to \sum_i \pi_i f(i)$ almost surely, *with or without* aperiodicity. The fraction of time spent in $i$ is $\pi_i$: this is just the LLN applied to i.i.d. excursions (renewal-reward), which links to yesterday's topic.

**Convergence theorem.** If additionally the chain is **aperiodic**, then $P(X_n = j) \to \pi_j$ from any start. Periodicity breaks this: the walk on a 2-cycle has $\pi = (1/2, 1/2)$ but $X_n$ alternates deterministically.

**Detailed balance (reversibility).** If $\pi_i P_{ij} = \pi_j P_{ji}$ for all $i, j$, summing over $i$ gives $\pi P = \pi$. Checking detailed balance is often much easier than solving $\pi P = \pi$. Key example: the **random walk on a graph** (move to a uniformly random neighbor) has

$$\pi_v = \frac{\deg(v)}{2|E|},$$

since $\pi_u P_{uv} = \frac{\deg u}{2|E|} \cdot \frac{1}{\deg u} = \frac{1}{2|E|}$ is symmetric in $u, v$.

**Classic application: the random knight.** A knight starts in a corner of an empty chessboard and moves uniformly at random. Expected number of moves to return to that corner? Summing knight-move counts over all 64 squares gives $\sum_v \deg v = 336$ (so $|E| = 168$). The corner has degree 2, so $\pi_{\text{corner}} = 2/336$ and by Kac, $m = 336/2 = 168$ moves. No linear system with 64 unknowns needed. (The knight graph is bipartite, so the chain is periodic, but Kac does not care.)

### 1.6 Common pitfalls

1. **Wrong state space.** Using "last flip" when the pattern can partially overlap itself. Always ask: does the future depend only on my state?
2. **Return time vs hitting time.** Kac gives the mean *return* time from a state to itself. The mean time to hit a state from a different start is a different number (see the HTH example below: return time 8, first-hit time 10).
3. **Forgetting the "1 +"** in hitting time equations, or adding it in the absorbing states.
4. **Non-unique solutions** on infinite chains (use the minimal one, or boundary conditions at infinity).
5. **Periodicity** breaks convergence of $P(X_n = j)$ but not time averages or Kac.

### 1.7 Interview question (Penney's game)

> A fair coin is flipped repeatedly.
> (a) What is the expected number of flips until HTH first appears? Until HHT?
> (b) I bet on HHT and you bet on HTH; we flip until one of them appears. What is the probability I win?
> (c) What is the expected length of that game?
> Bonus: any fixed window of 3 flips is HTH with probability $1/8$ and HHT with probability $1/8$. How can the waiting times differ?

### 1.8 Solution

**(a) HTH by first-step analysis.** The state is the longest suffix of the flips so far that is a prefix of HTH: $\varnothing$, H, HT (and the absorbing state HTH). Transitions:

- From $\varnothing$: H goes to H, T stays at $\varnothing$.
- From H: H stays at H (the suffix "H" still matches), T goes to HT.
- From HT: H completes HTH, T gives "HTT" whose longest useful suffix is empty, so back to $\varnothing$.

Let $e_s$ be the expected remaining flips from state $s$:

$$e_\varnothing = 1 + \tfrac12 e_H + \tfrac12 e_\varnothing \Rightarrow e_\varnothing = 2 + e_H,$$
$$e_H = 1 + \tfrac12 e_H + \tfrac12 e_{HT} \Rightarrow e_H = 2 + e_{HT},$$
$$e_{HT} = 1 + \tfrac12 \cdot 0 + \tfrac12 e_\varnothing.$$

So $e_\varnothing = 4 + e_{HT} = 5 + \tfrac12 e_\varnothing$, giving $\boxed{e_\varnothing = 10}$.

**HHT.** States $\varnothing$, H, HH:

- From H: H goes to HH, T gives "HT", no useful suffix, back to $\varnothing$.
- From HH: T completes HHT, H gives "HHH" whose suffix "HH" still matches, so stay at HH.

$$e_{HH} = 1 + \tfrac12 e_{HH} \Rightarrow e_{HH} = 2,$$
$$e_H = 1 + \tfrac12 e_{HH} + \tfrac12 e_\varnothing = 2 + \tfrac12 e_\varnothing,$$
$$e_\varnothing = 2 + e_H = 4 + \tfrac12 e_\varnothing \Rightarrow \boxed{e_\varnothing = 8}.$$

**Interview trick (Conway / the casino martingale).** For a pattern $A$ of length $L$ over a fair coin,

$$\mathbb{E}[N_A] = \sum_{k=1}^{L} 2^k \cdot \mathbf{1}\{\text{the length-}k\text{ prefix of } A \text{ equals its length-}k\text{ suffix}\}.$$

HTH: $k = 1$ (H = H) and $k = 3$ give $2 + 8 = 10$. HHT: only $k = 3$, so $8$. HH: $2 + 4 = 6$. HHH: $2 + 4 + 8 = 14$.

*Why it works.* Before each flip a new gambler arrives with \$1 and bets everything on the next letter of $A$ at fair odds, then keeps doubling on the following letters until he either loses or completes $A$. The casino's net gain is a martingale (fair bets). When $A$ first completes at time $N$, the casino has taken in $N$ dollars and pays out $2^k$ to each gambler still alive, which are exactly those who started at the beginning of a suffix of $A$ that is also a prefix. Optional stopping (topic 10 on the curriculum) gives $\mathbb{E}[N] = \sum (\text{payouts})$.

**(b) The race.** Now the states must track progress towards both patterns: $\varnothing$, H, HH, HT. Let $p_s$ be the probability that HHT wins from state $s$.

- From HH: we can never leave HH except by T, which completes HHT. So $p_{HH} = 1$. (Once you have HH, HTH is impossible before HHT: any T after the run of H's finishes HHT.)
- From HT: H completes HTH (I lose), T sends us to $\varnothing$. So $p_{HT} = \tfrac12 p_\varnothing$.
- From H: $p_H = \tfrac12 p_{HH} + \tfrac12 p_{HT} = \tfrac12 + \tfrac14 p_\varnothing$.
- From $\varnothing$: T keeps us at $\varnothing$, so $p_\varnothing = p_H$.

Hence $p = \tfrac12 + \tfrac14 p$, so $\boxed{p = 2/3}$. HHT beats HTH two times out of three.

**Conway's odds formula (trick).** Define the correlation number $XY = \sum_k 2^{k-1}\mathbf{1}\{\text{suffix of } X \text{ of length } k = \text{prefix of } Y \text{ of length } k\}$. With $A = $ HTH, $B = $ HHT: $AA = 101_2 = 5$, $AB = 001_2 = 1$, $BB = 100_2 = 4$, $BA = 010_2 = 2$. Then

$$\frac{P(B \text{ first})}{P(A \text{ first})} = \frac{AA - AB}{BB - BA} = \frac{5 - 1}{4 - 2} = 2,$$

so $P(B \text{ first}) = 2/3$. Note $\mathbb{E}[N_A] = 2 \cdot AA = 10$ and $\mathbb{E}[N_B] = 2 \cdot BB = 8$, consistent with (a).

**(c) Expected game length.** Let $t_s$ be the expected remaining flips:

$$t_{HH} = 1 + \tfrac12 t_{HH} \Rightarrow t_{HH} = 2, \qquad t_{HT} = 1 + \tfrac12 t_\varnothing,$$
$$t_H = 1 + \tfrac12 t_{HH} + \tfrac12 t_{HT} = \tfrac52 + \tfrac14 t_\varnothing, \qquad t_\varnothing = 2 + t_H = \tfrac92 + \tfrac14 t_\varnothing,$$

so $\boxed{t_\varnothing = 6}$. (Conway's version: $2\,\frac{AA \cdot BB - AB \cdot BA}{AA - AB + BB - BA} = 2 \cdot \frac{20 - 2}{6} = 6$.)

**Bonus: why the waiting times differ.** Run the chain whose state is the last three flips (8 states, uniform stationary distribution). By the ergodic theorem, occurrences of HTH and of HHT each have long-run frequency $1/8$, so the mean gap between consecutive occurrences is 8 for both. That is Kac. But HTH overlaps itself: after an HTH, the next HTH can come just 2 flips later (HTHTH). Occurrences of HTH **clump**, so the gaps are more variable: some are 2, so others must be longer than 8 to keep the mean at 8. HHT cannot overlap itself, so its occurrences are spread evenly. The first-hit time from scratch is like "arriving at a random time and waiting for the next bus": clumped buses mean a longer wait (the inspection paradox). Precisely, $\mathbb{E}[\text{first hit}] = $ mean return time $+$ (extra from self-overlap): $10 = 8 + 2$ for HTH.

**Sanity checks.** A simulation of 200,000 games gave $P(\text{HHT first}) \approx 0.6665$ and mean length $\approx 6.01$. Also, $6 < \min(8, 10)$ as it must be (the race ends at the first of the two hitting times), and the answer $2/3$ is above $1/2$, consistent with HHT having the shorter waiting time (though careful: in Penney's game a shorter wait does not always imply winning the race, which is why the game is non-transitive: THH beats HHT with probability $3/4$).

## 2. Derivatives: The Greeks and the Theta-Gamma Identity

Yesterday we built Black-Scholes (Garman-Kohlhagen for FX). Today is how a trader actually lives with an option: through its sensitivities. On an FX options desk in Hong Kong the morning risk report shows, per currency pair and per expiry bucket, the delta (in base currency), gamma (delta change per 1% spot move), vega (P&L per vol point), and theta (P&L per day). Everything a vol trader does is managing the trade-off between these.

### 2.1 Definitions and formulas (Garman-Kohlhagen)

Notation: spot $S$ (USD per EUR for EURUSD), strike $K$, time $T$, vol $\sigma$, domestic (USD) rate $r_d$, foreign (EUR) rate $r_f$, and

$$d_{1,2} = \frac{\ln(S/K) + (r_d - r_f \pm \tfrac12\sigma^2)T}{\sigma\sqrt T}, \qquad C = S e^{-r_f T} N(d_1) - K e^{-r_d T} N(d_2).$$

| Greek | Meaning | Call | Put |
|-------|---------|------|-----|
| Delta $\Delta = \partial V/\partial S$ | hedge ratio, in units of base currency per unit notional | $e^{-r_f T} N(d_1)$ | $-e^{-r_f T} N(-d_1)$ |
| Gamma $\Gamma = \partial^2 V/\partial S^2$ | how fast delta changes | $\dfrac{e^{-r_f T} n(d_1)}{S\sigma\sqrt T}$ | same |
| Vega $\nu = \partial V/\partial\sigma$ | P&L per unit of vol | $S e^{-r_f T} n(d_1)\sqrt T$ | same |
| Theta $\Theta = \partial V/\partial t$ | time decay | $-\dfrac{S e^{-r_f T} n(d_1)\sigma}{2\sqrt T} + r_f S e^{-r_f T}N(d_1) - r_d K e^{-r_d T}N(d_2)$ | analogous |
| Rho (two of them) | $\partial V/\partial r_d$, $\partial V/\partial r_f$ | $KTe^{-r_dT}N(d_2)$, $-STe^{-r_fT}N(d_1)$ | signs flip |

Calls and puts with the same strike have the **same gamma and vega** (put-call parity: $C - P$ is a forward, which is linear in $S$ and has no vol dependence). This is why a trader thinks of "vol risk" without caring whether it came from calls or puts.

The useful identity behind the gamma and vega formulas is $S e^{-r_f T} n(d_1) = K e^{-r_d T} n(d_2)$, which makes the $\partial d_i$ terms cancel when differentiating.

### 2.2 The P&L explain (Taylor expansion)

Over a short interval, with spot move $\delta S$ and vol move $\delta\sigma$:

$$\delta V \approx \Delta\,\delta S + \tfrac12\Gamma\,(\delta S)^2 + \nu\,\delta\sigma + \Theta\,\delta t + \underbrace{\frac{\partial^2 V}{\partial S\,\partial\sigma}}_{\text{vanna}}\delta S\,\delta\sigma + \tfrac12\underbrace{\frac{\partial^2 V}{\partial \sigma^2}}_{\text{volga}}(\delta\sigma)^2 + \dots$$

Risk systems produce exactly this decomposition every night; the residual (actual minus explained) is "unexplained P&L", and a large residual is a red flag (wrong market data, missing risk factor, or a booking error).

### 2.3 The theta-gamma identity

The Black-Scholes PDE in FX form is

$$\Theta + \tfrac12\sigma^2 S^2\Gamma + (r_d - r_f) S \Delta - r_d V = 0.$$

Read it as an accounting statement for a **delta-hedged, self-financed** position: what you lose to time decay is paid for by gamma, net of carry. Ignoring the small carry terms,

$$\Theta \approx -\tfrac12\sigma^2 S^2 \Gamma.$$

So over a time step $\delta t$, the delta-hedged P&L of a long option is approximately

$$\text{P\&L} \approx \tfrac12\Gamma S^2\left[\left(\frac{\delta S}{S}\right)^2 - \sigma^2\,\delta t\right].$$

You make money if the realized squared return beats the implied variance for that interval. The **breakeven move** is $|\delta S/S| = \sigma\sqrt{\delta t}$; for one day, $\sigma/\sqrt{365}$ (or $\sigma/\sqrt{252}$ if you count trading days, a convention that matters for weekend theta). Long gamma = long realized vol, short theta. Short gamma = collecting theta and praying for quiet markets. There is no free lunch: you cannot be long gamma and long theta at the same time in a vanilla book.

### 2.4 How the Greeks depend on strike and expiry

For ATM options, the key scalings (using $n(d_1) \approx n(0) \approx 0.4$):

- Price $\approx 0.4\,S\sigma\sqrt T$
- Vega $\approx 0.4\,S\sqrt T$: grows like $\sqrt T$. Long-dated options are "vega trades".
- Gamma $\approx \dfrac{0.4}{S\sigma\sqrt T}$: blows up like $1/\sqrt T$. Short-dated options are "gamma trades".
- Theta $\approx -\dfrac{0.4\,S\sigma}{2\sqrt T}$: also $1/\sqrt T$, so decay accelerates into expiry.

Across strikes (fixed $T$), gamma and vega peak near the forward and fall off in the wings. Delta goes from 0 to $e^{-r_f T}$, crossing about 0.5 near ATM. FX markets literally quote options by delta (25-delta, 10-delta), which we will cover later in the curriculum.

Second-order Greeks that matter in FX:

- **Vanna** $\partial\Delta/\partial\sigma$: how your delta changes when vol moves. Crucial for risk reversals and when spot and vol are correlated (USDJPY selling off with vol up).
- **Volga** (vomma) $\partial\nu/\partial\sigma$: convexity in vol. Wings have large volga; this is why butterflies are priced above flat-vol value.
- **Charm** $\partial\Delta/\partial t$: delta drift overnight. Matters for big books on Friday.
- **Speed** $\partial\Gamma/\partial S$: gamma is not constant; large moves are not captured by the quadratic term.

### 2.5 Worked scenario: Greeks and P&L explain on a 1M EURUSD call

You buy a **1-month (30-day) EUR call / USD put, ATM spot strike**, notional **EUR 10 million**. Market (illustrative): $S = K = 1.1000$, $\sigma = 8.0\%$, $r_{USD} = 4.0\%$, $r_{EUR} = 2.0\%$, $T = 30/365 = 0.08219$.

**Step 1: $d_1, d_2$.** $\sigma\sqrt T = 0.08 \times 0.28669 = 0.022935$.
$d_1 = \dfrac{0 + (0.04 - 0.02 + 0.0032)(0.08219)}{0.022935} = \dfrac{0.0019068}{0.022935} = 0.0831$, $d_2 = 0.0831 - 0.0229 = 0.0602$.

**Step 2: price.** $C = 0.010967$ USD per EUR, i.e. **109.7 USD pips**, or **USD 109,675** on EUR 10M (about 1.00% of the USD notional). Rule of thumb check: $0.4 \times 1.1 \times 0.08 \times 0.2867 = 0.01009$; the actual price is a bit higher because the strike is below the forward ($F = 1.1 e^{0.02 \times 0.0822} = 1.1018$), so the call is slightly in the money forward.

**Step 3: Greeks.**

| Greek | Per EUR 1 | On EUR 10M | Desk units |
|-------|-----------|------------|------------|
| Delta | $e^{-r_fT}N(d_1) = 0.5323$ | EUR 5.32M | 53.2% delta: hedge by selling EUR 5.32M spot |
| Gamma | $15.73$ per unit of $S$ | | delta changes by EUR 1.73M per 1% spot move ($15.73 \times 0.011 \times 10\text{M}$) |
| Vega | $0.1252$ per unit vol | USD 12,517 per vol point | |
| Theta | | USD $-1{,}978$ per day | |
| Vanna | $-0.299$ per unit vol | delta falls by EUR 29.9k per +1 vol | |

Check with the rule of thumb: vega $\approx 0.4 \times 1.1 \times 0.2867 \times 0.01 \times 10\text{M} = 12{,}614$. Close.

**Step 4: theta-gamma check.** Pure gamma cost per day: $\tfrac12\sigma^2 S^2 \Gamma / 365 \times 10\text{M} = \text{USD } 1{,}669$. Carry pieces per day: $-(r_d - r_f) S \Delta/365 \times 10\text{M} = -321$ and $+r_d C/365 \times 10\text{M} = +12$. Total: $-1{,}669 - 321 + 12 = -1{,}978$. The PDE balances exactly. The hedge (short EUR 5.32M, long USD) earns the 2% rate differential, which is why, once the hedge's carry is included, the economic breakeven is driven by the 1,669 gamma piece.

**Step 5: breakeven move.** $\sigma/\sqrt{365} = 0.08/19.10 = 0.419\%$ per day, about **46 pips** in EURUSD. If spot moves more than about 46 pips (up or down) in a day and you re-hedge, gamma pays for theta.

**Step 6: a day later, EURUSD rallies 1% to 1.1110 and vol rises to 8.5%.** Full revaluation (29 days left): the position is worth USD 181,040, a gain of **USD 71,365**. The Taylor explain:

| Component | Formula | USD |
|-----------|---------|-----|
| Delta | $0.5323 \times 0.0110 \times 10\text{M}$ | +58,548 |
| Gamma | $\tfrac12 \times 15.73 \times 0.011^2 \times 10\text{M}$ | +9,518 |
| Vega | $12{,}517 \times 0.5$ | +6,259 |
| Theta | one day | $-1{,}978$ |
| Vanna | $-0.299 \times 0.011 \times 0.005 \times 10\text{M}$ | $-164$ |
| Volga | $\tfrac12 \times (-0.30) \times 0.005^2 \times 10\text{M}$ | $-38$ |
| **Explained** | | **72,145** |
| Unexplained | third-order (speed, charm) | $-780$ |

If you had been delta-hedged (short EUR 5.32M from the start), the hedge loses the 58,548 delta piece, leaving about **+12,817**: a 1% move is 2.4 breakeven moves, so gamma earned $\tfrac12\Gamma S^2 (0.01)^2 \approx 9{,}518$, about 5.7 times the 1,669 daily gamma cost, plus the vol pop. The residual of $-780$ is about 1% of the move: speed (gamma is lower at 1.1110 than at 1.1000 for this strike) and the fact that gamma itself decays over the day. On a 5% move, the quadratic approximation would be far worse, which is why desks run full-revaluation spot ladders, not just Greeks.

**Step 7: the quiet day.** If spot and vol do not move, the position loses about USD 1,992 (slightly more than the instantaneous theta of 1,978, because decay accelerates as expiry approaches). Five quiet days lose about USD 10k: that is what owning gamma costs.

### 2.6 How the Greeks change with expiry (same 1.1000 ATM, EUR 10M)

| Expiry | Gamma (per unit S) | Vega per vol (USD) | Theta per day (USD) |
|--------|--------------------|--------------------|---------------------|
| 1 day | 86.6 | 2,297 | $-9{,}489$ |
| 1 week | 32.7 | 6,070 | $-3{,}774$ |
| 1 month | 15.7 | 12,517 | $-1{,}978$ |
| 3 months | 9.0 | 21,460 | $-1{,}266$ |
| 1 year | 4.3 | 41,243 | $-765$ |

The $\sqrt T$ and $1/\sqrt T$ laws are visible: from 1 month to 1 year ($12\times$), vega grows about $3.3\times$ and gamma falls about $3.7\times$ (not exactly $\sqrt{12} = 3.46$ because the forward drifts away from the spot strike).

### 2.7 What can go wrong

- **Pin risk near expiry:** ATM gamma explodes as $T \to 0$. A big short gamma position at a strike near spot on expiry day (often around a 10am New York or 3pm Tokyo cut) can flip delta from 0 to 100% with a few pips.
- **Smile dynamics:** the Black-Scholes delta assumes vol stays fixed when spot moves. In reality the implied vol at your strike changes with spot (sticky strike vs sticky delta). The "smile-adjusted" delta adds vanna times $d\sigma/dS$. In USDJPY, where spot down usually comes with vol up, the difference is material.
- **Vega is not one number:** 1-week vol and 1-year vol do not move together. Books report vega by expiry bucket (and often weight it by $1/\sqrt T$ to reflect that short-dated vols move more).
- **Jumps and gaps:** delta hedging assumes continuous paths. A central bank intervention (e.g. a sudden 3-4 big figure move in USDJPY) delivers the P&L of a huge move on a short-gamma book before you can hedge.
- **Theta conventions:** calendar vs business day theta, and weekend vol. Many FX desks put lower variance on weekends and holidays, so Friday's theta is large.

### 2.8 Likely interview questions

1. **"You are long a delta-hedged ATM straddle and the market does not move all week. What is your P&L? What if realized vol equals implied?"** You lose theta every day. If realized vol equals implied, on average gamma gains offset theta and the expected P&L is about zero (path matters: gains depend on where spot is relative to strike when the moves happen, since gamma is not constant).
2. **"Is delta the probability the option finishes in the money?"** Not quite. The risk-neutral probability of exercise is $N(d_2)$; the delta is $e^{-r_f T}N(d_1)$. They differ by roughly $n(d)\sigma\sqrt T$, which is small for short-dated, low-vol options, but material for long-dated or high-vol ones. Delta is the probability under the measure using the foreign currency as numeraire.
3. **"Why is gamma highest ATM and what happens to it as expiry approaches?"** Delta is a smoothed step function: it moves from 0 to 1 over a region about $S\sigma\sqrt T$ wide around the strike. Gamma is its slope, peaking at the strike with height about $1/(S\sigma\sqrt T \sqrt{2\pi})$. As $T \to 0$ the step sharpens, ATM gamma goes to infinity while OTM gamma goes to zero.

## 3. Algorithms & Data Structures: The Skyline Problem (Sweep Line)

### 3.1 Problem

You are given $n$ buildings, each a rectangle $[\text{left}_i, \text{right}_i) \times [0, \text{height}_i]$ on flat ground. Return the **skyline**: the outer contour of their union, as a list of "key points" $[x, y]$ sorted by $x$. Each key point is the left end of a horizontal segment of the contour; the last key point always has $y = 0$ and marks where the rightmost building ends. There must be **no consecutive key points with the same height** (merge them).

Constraints: $1 \le n \le 10^4$, $0 \le \text{left}_i < \text{right}_i \le 2^{31} - 1$, $1 \le \text{height}_i \le 2^{31} - 1$, buildings sorted by left edge (we will not rely on that).

Example 1:

```
Input:  [[2,9,10],[3,7,15],[5,12,12],[15,20,10],[19,24,8]]
Output: [[2,10],[3,15],[7,12],[12,0],[15,10],[20,8],[24,0]]
```

Example 2 (touching buildings with the same height merge):

```
Input:  [[0,2,3],[2,5,3]]
Output: [[0,3],[5,0]]
```

### 3.2 From first principles

**Brute force.** The skyline height at $x$ is $h(x) = \max\{\text{height}_i : \text{left}_i \le x < \text{right}_i\}$ (0 if none). The function $h$ can only change at a building edge. Collect all $2n$ edge coordinates, sort and deduplicate them, and for each one compute $h(x)$ by scanning all buildings; emit $(x, h(x))$ whenever it differs from the previous height. That is $O(n^2)$: about $2 \times 10^8$ operations at $n = 10^4$, borderline. (A pixel grid over $x$ is hopeless: coordinates go to $2^{31}$.)

**Insight 1: sweep line.** Move a vertical line from left to right. At each edge, the set of "active" buildings (those the line currently cuts) changes by one insertion (left edge) or one deletion (right edge). Between edges, nothing changes. So the problem reduces to maintaining a dynamic set of heights under insert and delete, with **max queries**. This is the general sweep-line recipe: convert intervals into $2n$ sorted events and maintain a data structure that summarizes the active intervals.

**Insight 2: the right data structure.** We need insert, delete an arbitrary element, and find max, all in $O(\log n)$:

- A balanced BST (`std::multiset`) does all three directly. Must be a *multi*set because heights repeat.
- A max-heap (`std::priority_queue`) does insert and max but cannot delete an arbitrary element. Use **lazy deletion** (as in yesterday's sliding median): store (height, right edge), and when you look at the top, pop it if its right edge is $\le x$ (the building has already ended). Stale entries buried deeper do no harm until they surface.

**Insight 3: ties.** Several events can share the same $x$ (Example 2: one building ends at 2 and another starts at 2). If you processed them one by one and emitted a point after each, you could output $[2, 0]$ then $[2, 3]$, which is wrong. The clean fix: apply **all events at the same $x$ first**, then compare the new max with the previous max once. (A common alternative is a tie-breaking sort order: starts before ends, taller starts first, shorter ends first. It works, but the batch approach is easier to get right under interview pressure.)

**Algorithm (multiset).**

1. For each building, create events $(\text{left}, +h)$ and $(\text{right}, -h)$.
2. Sort events by $x$.
3. Keep a multiset `active` initialized with $\{0\}$ (ground), so the max is always defined.
4. For each distinct $x$: insert all $+h$, erase one copy of each $-h$. Let `cur = max(active)`. If `cur != prev`, output $(x, \text{cur})$ and set `prev = cur`.

**Complexity.** Sorting $2n$ events: $O(n \log n)$. Each multiset operation is $O(\log n)$, $2n$ of them. Total $O(n \log n)$ time, $O(n)$ space. The heap version is also $O(n \log n)$ (each building is pushed and popped at most once).

**Why the output has no duplicate heights:** we only emit when the max changes, and we emit at most one point per distinct $x$.

### 3.3 C++ solution

```cpp
// Daily Quant Digest 2026-10-19
// Algorithms & DS: Intervals and sweep line, "The Skyline Problem"
// Compile: g++ -std=c++17 -O2 -Wall 2026-10-19.cpp -o skyline && ./skyline

#include <algorithm>
#include <cassert>
#include <iostream>
#include <queue>
#include <random>
#include <set>
#include <utility>
#include <vector>

using std::vector;
using Building = std::vector<long long>;          // {left, right, height}
using Point = std::pair<long long, long long>;    // {x, height}

// ---------------------------------------------------------------------------
// Solution 1: sweep line with a multiset of active heights. O(n log n).
// ---------------------------------------------------------------------------
vector<Point> getSkyline(const vector<Building>& buildings) {
    // Each building produces two events: +h at its left edge, -h at its right edge.
    vector<Point> events;
    events.reserve(2 * buildings.size());
    for (const auto& b : buildings) {
        events.emplace_back(b[0], b[2]);    // start: positive height
        events.emplace_back(b[1], -b[2]);   // end:   negative height
    }
    // Sort by x only. All events at the same x are applied as a batch below,
    // so we do not need any clever tie-breaking rule.
    std::sort(events.begin(), events.end(),
              [](const Point& a, const Point& b) { return a.first < b.first; });

    std::multiset<long long> active{0};     // ground level is always "active"
    vector<Point> result;
    long long prevMax = 0;

    std::size_t i = 0;
    while (i < events.size()) {
        const long long x = events[i].first;
        // Apply every event that happens at this x.
        while (i < events.size() && events[i].first == x) {
            const long long h = events[i].second;
            if (h > 0) {
                active.insert(h);
            } else {
                // erase ONE copy: erase(value) would remove all equal heights
                active.erase(active.find(-h));
            }
            ++i;
        }
        const long long curMax = *active.rbegin();   // largest element
        if (curMax != prevMax) {
            result.emplace_back(x, curMax);
            prevMax = curMax;
        }
    }
    return result;
}

// ---------------------------------------------------------------------------
// Solution 2: sweep over sorted x with a max-heap and lazy deletion. O(n log n).
// Heap stores {height, right edge}; tops whose right edge <= x are stale.
// ---------------------------------------------------------------------------
vector<Point> getSkylineHeap(vector<Building> buildings) {
    std::sort(buildings.begin(), buildings.end());   // by left edge
    vector<long long> xs;
    for (const auto& b : buildings) { xs.push_back(b[0]); xs.push_back(b[1]); }
    std::sort(xs.begin(), xs.end());
    xs.erase(std::unique(xs.begin(), xs.end()), xs.end());

    std::priority_queue<Point> heap;   // max-heap on height
    vector<Point> result;
    std::size_t j = 0;
    long long prevMax = 0;
    for (long long x : xs) {
        while (j < buildings.size() && buildings[j][0] == x) {
            heap.emplace(buildings[j][2], buildings[j][1]);
            ++j;
        }
        while (!heap.empty() && heap.top().second <= x) heap.pop();   // lazy delete
        const long long curMax = heap.empty() ? 0 : heap.top().first;
        if (curMax != prevMax) {
            result.emplace_back(x, curMax);
            prevMax = curMax;
        }
    }
    return result;
}

// ---------------------------------------------------------------------------
// Brute force reference: height on each elementary interval [xs[k], xs[k+1]).
// O(n^2), used only for testing.
// ---------------------------------------------------------------------------
vector<Point> bruteForce(const vector<Building>& buildings) {
    vector<long long> xs;
    for (const auto& b : buildings) { xs.push_back(b[0]); xs.push_back(b[1]); }
    std::sort(xs.begin(), xs.end());
    xs.erase(std::unique(xs.begin(), xs.end()), xs.end());
    vector<Point> result;
    long long prev = 0;
    for (long long x : xs) {
        long long h = 0;
        for (const auto& b : buildings)
            if (b[0] <= x && x < b[1]) h = std::max(h, b[2]);
        if (h != prev) { result.emplace_back(x, h); prev = h; }
    }
    return result;
}

void print(const vector<Point>& pts) {
    std::cout << "[";
    for (std::size_t k = 0; k < pts.size(); ++k)
        std::cout << (k ? "," : "") << "[" << pts[k].first << "," << pts[k].second << "]";
    std::cout << "]\n";
}

int main() {
    // Example 1
    vector<Building> ex1 = {{2, 9, 10}, {3, 7, 15}, {5, 12, 12}, {15, 20, 10}, {19, 24, 8}};
    vector<Point> want1 = {{2, 10}, {3, 15}, {7, 12}, {12, 0}, {15, 10}, {20, 8}, {24, 0}};
    auto got1 = getSkyline(ex1);
    print(got1);
    assert(got1 == want1 && getSkylineHeap(ex1) == want1);

    // Example 2: touching buildings of equal height merge into one segment
    vector<Building> ex2 = {{0, 2, 3}, {2, 5, 3}};
    vector<Point> want2 = {{0, 3}, {5, 0}};
    auto got2 = getSkyline(ex2);
    print(got2);
    assert(got2 == want2 && getSkylineHeap(ex2) == want2);

    // Example 3: identical buildings, and one hidden inside another
    vector<Building> ex3 = {{1, 5, 4}, {1, 5, 4}, {2, 3, 2}};
    vector<Point> want3 = {{1, 4}, {5, 0}};
    auto got3 = getSkyline(ex3);
    print(got3);
    assert(got3 == want3 && getSkylineHeap(ex3) == want3);

    // Example 4: a taller building starts exactly where a shorter one ends
    vector<Building> ex4 = {{1, 3, 2}, {3, 6, 5}, {6, 8, 5}};
    vector<Point> want4 = {{1, 2}, {3, 5}, {8, 0}};
    auto got4 = getSkyline(ex4);
    print(got4);
    assert(got4 == want4 && getSkylineHeap(ex4) == want4);

    // Randomised cross-check against brute force (lots of ties on purpose)
    std::mt19937 rng(20261019);
    for (int trial = 0; trial < 20000; ++trial) {
        int n = 1 + rng() % 8;
        vector<Building> bs;
        for (int k = 0; k < n; ++k) {
            long long l = rng() % 10, w = 1 + rng() % 5, h = 1 + rng() % 4;
            bs.push_back({l, l + w, h});
        }
        auto ref = bruteForce(bs);
        assert(getSkyline(bs) == ref);
        assert(getSkylineHeap(bs) == ref);
    }
    std::cout << "All tests passed.\n";
    return 0;
}
```

### 3.4 Walkthrough of the C++

- **Type aliases with `using`.** `using Point = std::pair<long long, long long>;` is the modern replacement for `typedef`. It keeps signatures readable. `long long` avoids overflow worries since heights go up to $2^{31} - 1$ and we negate them (and sums or differences of coordinates near $2^{31}$ would overflow an `int`).
- **`reserve` and `emplace_back`.** `events.reserve(2 * n)` allocates once, so the $2n$ insertions never reallocate. `emplace_back(b[0], b[2])` constructs the `pair` in place from its arguments instead of building a temporary and copying it.
- **`const auto& b : buildings`.** A range-based for loop that binds each element by const reference. Writing `auto b` would copy each inner `vector` (a heap allocation per building). This is one of the most common silent performance bugs in interview C++.
- **Lambda comparator.** `std::sort(..., [](const Point& a, const Point& b) { return a.first < b.first; })` sorts by $x$ only. The `[]` is an empty capture list (the lambda uses nothing from the enclosing scope). Because we batch by $x$ afterwards, the order within the same $x$ is irrelevant, so we do not even need `stable_sort`. The comparator must be a strict weak ordering: use `<`, never `<=`, or `std::sort` has undefined behavior.
- **`std::multiset<long long> active{0};`** A red-black tree that keeps elements sorted and allows duplicates. Brace-initialization inserts the ground level 0.
- **`active.erase(active.find(-h))`, the classic trap.** `multiset::erase(value)` removes **every** element equal to `value` (and returns how many). If two buildings of height 15 overlap and one ends, `erase(15)` would delete both. `find` returns an iterator to one copy, and `erase(iterator)` removes exactly that one. Each building's height was inserted before its end event, so `find` cannot return `end()` here.
- **`*active.rbegin()`.** `rbegin()` is a reverse iterator to the last (largest) element; dereferencing it gives the max in $O(1)$. `*std::prev(active.end())` is equivalent.
- **Two-level `while` loop.** The outer loop picks the next $x$; the inner loop consumes every event with that $x$. Using an explicit index `i` shared by both loops is the idiomatic way to do "group by" over a sorted vector.
- **`std::priority_queue<Point>`.** A max-heap. `std::pair` compares lexicographically, so the top is the tallest building (ties broken by larger right edge, which is harmless). Lazy deletion: `while (!heap.empty() && heap.top().second <= x) heap.pop();` throws away buildings that have already ended. Always check `empty()` before `top()`: calling `top()` on an empty heap is undefined behavior, not an exception.
- **Sort-unique-erase idiom.** `std::unique` moves consecutive duplicates to the end and returns an iterator to the new logical end; `erase` then shrinks the vector. It only removes *adjacent* duplicates, so sort first.
- **`std::sort` on `vector<vector<long long>>`.** Vectors compare lexicographically, so `buildings` gets sorted by left edge (then right, then height).
- **Testing with `assert` and `std::mt19937`.** The random test generates small buildings with many ties (coordinates in $[0, 14]$, heights in $[1, 4]$) and checks both solutions against the $O(n^2)$ brute force 20,000 times. Small ranges are deliberate: they maximize collisions, which is where sweep-line bugs live. `vector<pair>` supports `==`, so comparing whole outputs is one line.

### 3.5 Variations to be ready for

- **Meeting Rooms II** (minimum number of rooms = maximum overlap): same events, but the "data structure" is just a counter. Sort events with ends before starts at equal times for half-open intervals.
- **Merge Intervals / Insert Interval:** sort by start, sweep, extend the current block while the next start $\le$ current end.
- **Employee Free Time:** merge everyone's intervals, then output the gaps.
- **Area of the union of rectangles:** sweep in $x$, and maintain the covered length in $y$ with a segment tree over compressed $y$ coordinates (curriculum topic 16). The skyline is the special case where all rectangles touch the ground, so a max replaces the coverage count.
- **Order book analogy:** the multiset of active heights is like a price level book where you need the best bid under inserts and cancels. Real matching engines use the same trick (a sorted structure keyed by price, or a heap with lazy cancellation).
